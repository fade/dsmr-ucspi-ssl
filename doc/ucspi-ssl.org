* TL;DR
:PROPERTIES:
:DESCRIPTION: What ucspi-ssl provides and how DSMR uses it.
:END:

=ucspi-ssl= packages the fehcom.de fork of ucspi-ssl (0.13.07, Erwin Hoffmann),
which already supports OpenSSL 3.x and TLS 1.3. It provides UCSPI-style TCP
wrappers that layer TLS onto a plain server program's stdin/stdout — chiefly
*sslserver* (a TLS-capable =tcpserver= replacement) and *sslclient*. In the DSMR
stack the qmail SMTP/submission supervise scripts use =sslserver= to terminate
TLS in front of =qmail-smtpd=.

This manual documents *what the DSMR packaging does and how the stack uses it* —
the single Debian patch, the fehQlibs linkage, the qmail integration, and the
certificate convention. The per-command reference is the upstream man pages
shipped with the package (*sslserver(1)*, *sslclient(1)*, …); this manual does
not re-derive them.

The package installs to =/usr/bin/=: =sslserver=, =sslclient=, =sslhandle=,
=sslconnect=, =sslcat=, =https@=, and =sslprint=, plus their man pages.

* Theory of operation
:PROPERTIES:
:DESCRIPTION: The UCSPI convention, what the one Debian patch changes.
:END:

** The UCSPI convention
UCSPI (Unix Client-Server Program Interface) separates a network program from
its transport. A server reads from descriptor 0 and writes to 6 (the client
half on 7); the wrapper does the bind/accept and — with ucspi-ssl — the TLS
handshake, then execs the application. The application need not know TLS exists:
=sslserver -n cert.pem 0 587 qmail-smtpd= accepts a connection on port 587,
negotiates TLS, and hands =qmail-smtpd= a clean byte stream plus a set of
=SSL_*= environment variables describing the session.

** What the DSMR packaging changes
ucspi-ssl uses a DJB-style build (=package/compile=), not autotools. The Debian
packaging applies exactly *one* quilt patch, =debian-install-paths.patch=, which
rewrites two upstream =conf-= files:

- =conf-home=: =/usr/local= → =/usr=, so binaries install to =/usr/bin= (FHS,
  not =/usr/local/bin=);
- =conf-qlibs=: =/usr/local/qlibs= → =/usr/lib/fehqlibs=, pointing the build at
  Debian's *fehqlibs-dev* install location.

No OpenSSL-3 or TLS-1.3 compatibility patch is needed — the fehcom.de fork
already carries that upstream. The =debian/rules= overrides drive the custom
build (=package/compile base= in =override_dh_auto_configure=), install the
commands listed in =package/commands-base=, and install the upstream =man/*.1=
and =man/*.2= pages as-is.

** Relationship to fehQlibs
=sslclient= uses *fehqlibs* (=-ldnsresolv=) for DNSSEC-aware verification of the
peer hostname against the presented certificate. That is why =fehqlibs-dev= is a
build dependency and why =conf-qlibs= must point at =/usr/lib/fehqlibs=.

* Usage
:PROPERTIES:
:DESCRIPTION: The installed commands and the qmail invocation.
:END:

| Command      | Role                                                        |
|--------------+-------------------------------------------------------------|
| =sslserver=  | TLS-accepting server wrapper (like =tcpserver=)             |
| =sslclient=  | TLS-connecting client wrapper                               |
| =sslhandle=  | preforking TLS server for concurrent connections            |
| =sslconnect= | lower-level TLS connection initiator                        |
| =sslcat=     | pipe stdin/stdout through a one-shot TLS connection         |
| =https@=     | minimal HTTPS GET client                                    |
| =sslprint=   | diagnostic: dump the negotiated TLS session and =SSL_*= env |

The DSMR qmail submission service wraps =qmail-smtpd= with =sslserver=:

: exec /usr/bin/sslserver -e -v \
:     -n /etc/qmail/servercert.pem \
:     0 587 \
:     /var/qmail/bin/qmail-smtpd 2>&1

The =-n= flag names the combined cert+key PEM. After the handshake the child
sees the peer and cipher in its environment (see Configuration). Inspect a
session interactively with =sslprint=, or verify the cert with =https@= /
=sslcat= against a live endpoint.

* Configuration
:PROPERTIES:
:DESCRIPTION: The certificate, DH parameters, and the SSL_* environment.
:END:

- *Certificate* :: =sslserver= / =sslclient= expect a single PEM holding *both*
  the certificate and its private key. The *qmail* package generates exactly
  that at =/etc/qmail/servercert.pem=; ucspi-ssl ships no certificate of its own.
- *DH parameters* :: supplied via the build's =conf-dhfile= default or overridden
  at runtime; perfect-forward-secrecy negotiation uses it.

=sslserver= sets these =SSL_*= variables in the child environment:

| Variable       | Content                                        |
|----------------+------------------------------------------------|
| =PROTO=        | =SSL=                                          |
| =SSL_PROTOCOL= | negotiated version, e.g. =TLSv1.3=             |
| =SSL_CIPHER=   | negotiated cipher suite                        |
| =SSL_CLIENT_*= | peer-certificate subject DN fields, if present |
| =TCPREMOTEIP=  | peer IP address (UCSPI-TCP carry-over)         |

* Extension points
:PROPERTIES:
:DESCRIPTION: Cipher/version tuning and certificate chaining.
:END:

- *Tune TLS version and cipher suites* per the upstream notes in
  =doc/TLSVERSION_CIPHERSUITES= (pre-1.3 =SSL_CIPHER= controls vs the 1.3
  ciphersuite syntax).
- *Certificate chaining* (intermediate CAs) follows =doc/CHAIN-SSL=.
- *Front any plain UCSPI server with TLS* by substituting =sslserver= for
  =tcpserver= — the wrapped program is unchanged; this is exactly how the qmail
  services gain STARTTLS/implicit-TLS without modifying =qmail-smtpd=.

* Gotchas and debugging
:PROPERTIES:
:DESCRIPTION: Combined PEM, the fehQlibs path, and OpenSSL 3.
:END:

- *One PEM, both halves.* A cert file with only the certificate (no private key)
  makes =sslserver= fail the handshake. =/etc/qmail/servercert.pem= must contain
  the cert *and* the key — =grep -c BEGIN= should report at least 2.
- *The fehQlibs path must match the install.* If a rebuild can't find =-lqlibs= /
  =-ldnsresolv=, =conf-qlibs= is not pointing at =/usr/lib/fehqlibs= — the
  =debian-install-paths.patch= sets that; keep it applied.
- *No OpenSSL-3 patch required.* If TLS 1.3 or a modern cipher seems unavailable,
  it is a configuration/cert issue, not a missing patch — the 0.13.07 fork
  supports both natively.
- *Diagnose with =sslprint=.* To see exactly what version/cipher a client
  negotiated and which =SSL_*= variables the child would receive, run the
  endpoint behind =sslprint= instead of the real service for one connection.
